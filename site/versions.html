How the version selector works

Deliberately boring, so that it cannot break.

  • The current documentation always lives at the site root. It describes the commit named in the bar at the top of each page.
  • Each released major version gets a frozen copy under /v/<version>/. A direct link to an old version keeps working after the current pages move on.
  • The list of versions comes from versions.json, a small static file committed to the repository. It is read when a page is written, not when a page is viewed — there is no backend, no JavaScript requirement and no GitHub API call at runtime.
  • The selector itself is a plain disclosure widget holding ordinary links, so it works with JavaScript disabled and is keyboard operable without any custom code.
  • tools/check_site.py checks that every entry in the manifest resolves, that every archived directory appears in the manifest, that the selector on each page lists every version, and that every page carries a version, a source ref and a review date. It runs in CI on every pull request that touches the site, and takes --release vX.Y.Z for an advisory release-readiness check that a human runs before a version is tagged.

What a release will never contain

No ROM. No save file. No base.zip. No extracted game data, generated asset source, texture dump or audio bank. No compiled playable binary. A built binary of this port has the entire game compiled into it, which is not this project's to distribute. Renaming, compressing or encoding any of the above does not make it allowed. The reasoning is in docs/LICENSING.md; the rule is in AGENTS.md.
