Install it

Written for someone who has never built a project before. Pick your operating system, follow the steps in order, and read the two rules first — they explain the one thing that is genuinely different about this project.

Two rules, before anything else

1. You supply the game. This project supplies the program. Installing builds the game on your computer from your own copy of GoldenEye 007 for the Nintendo 64 — a cartridge dump file that you already have and are permitted to use. The installer reads that file where it sits. It does not copy it, move it, modify it or upload it anywhere.
2. Nothing here distributes the game, and nothing ever will. There is no ROM to download, no extracted assets, and no ready-made playable binary — not on this site, not in the repository, and not in a release. This is not an oversight and it is not coming later: a built copy of this port has the entire game compiled into it, which is not this project's to hand out. It is yours to build for yourself.

This page will not tell you where to obtain game data, and no page here ever will — not out of squeamishness, but because downloading a ROM is an unauthorised reproduction even if you own the cartridge, which is one of the few genuinely settled points in this area. Linking to one would put the project on the wrong side of the one line it can actually be sure about.

Which parts of this are settled and which are genuinely unresolved is set out in the FAQ; the provenance record is docs/LICENSING.md. Both are factual records, not legal advice, and using a dump and the build you make from it in a way permitted where you live is your responsibility.

What you need

The same three things on every platform.

Your own cartridge dump

The US retail GoldenEye 007 for Nintendo 64. Big-endian .z64 is what the build wants; the macOS and Linux installers also accept .n64 and .v64 byte orders.

About 4 GB free

Sources, dependencies, the extracted data and the build all live in that space.

10–40 minutes, once

And an internet connection for the first run, which downloads the open-source dependencies. Later runs are much shorter.

Re-running an installer is always safe. Each step checks whether its own output already exists and skips it, so a run that stopped halfway is resumed by running the same command again.

macOS

The double-click path. No terminal required.

  1. Put your ROM on the Desktop

    Leave the filename alone. The installer looks on your Desktop and in Downloads for a supported dump.

  2. Download the project

    On the project page, click the green Code button, then Download ZIP. Double-click the downloaded file to unzip it.

  3. Double-click Install on Mac

    It is in the folder you just unzipped. If Gatekeeper blocks it, right-click the file, choose Open, and confirm once.

    A Terminal window opens and does the work. Leave it alone until it finishes. This is the 10–40 minute part, and it only happens once.

  4. Play

    Open getv/build-mac and double-click GoldenEye.app. The launcher opens directly. Play GoldenEye in the project folder is a direct shortcut to the same build.

    Keep the app beside the goldeneye executable, including if you move the folder — the app uses the executable next to it and does not contain its own copy of the game. You can drag the app to the Dock.

If you would rather use the terminal

bash tools/install.sh

Run it from the project folder. Pass an explicit path only if the installer cannot find your dump:

bash tools/install.sh --rom /path/to/your/rom.z64

Apple silicon and Intel Macs are separate native targets. The standard installer builds the OpenGL renderer; the separate Metal build is described under Renderer and in docs/GETTING_STARTED.md.

Linux

One command, from the project folder.

  1. Install git and python3

    From your distribution's package manager. These are the only system packages you need in advance.

  2. Get the project and open a terminal in it

    Clone it, or download and unzip it — either is fine.

    git clone https://github.com/seb-patron/goldeneye-native.git
cd goldeneye-native

  3. Run the installer

    bash tools/install.sh

    It finds a supported dump on your Desktop or in Downloads. It never runs sudo: if a system dependency is missing it prints the exact package-manager command for your distribution and stops. Install that package, then run the same command again.

    To point at a specific file, or to add a per-user applications-menu entry:

    bash tools/install.sh --rom /path/to/your/rom.z64
bash tools/install.sh --rom /path/to/your/rom.z64 --desktop

  4. Play

    ./getv/build-linux/goldeneye --launcher

    Omit --launcher to boot straight into the game with your current settings.

Windows

The no-code Windows setup app is a release candidate and is not published yet. There is no official Windows download and no release automation. The GitHub Actions workflow validates a setup candidate inside the runner and deliberately does not upload it.

Do not download a setup executable from an Actions run or from a third-party repost. Until this repository's Releases page lists a coordinated Windows package, the no-code Windows path is not available. Use the developer path below in the meantime.

The developer path, available today

  1. Install Git for Windows and Python 3

    Both from their official installers. This path, unlike the setup app, does expect them.

  2. Get the project

    git clone https://github.com/seb-patron/goldeneye-native.git
cd goldeneye-native

  3. Run the installer in PowerShell

    powershell -NoProfile -ExecutionPolicy Bypass -File tools\install.ps1 -Rom C:\path\to\your-rom.z64

    It accepts .z64, .v64 and .n64 byte orders, and downloads the MinGW toolchain and the libraries this project uses. No MSYS2, Cygwin or WSL is involved and none is installed.

  4. Play

    .\getv\build-windows\goldeneye.exe

    Double-clicking the executable opens the launcher. Play GoldenEye.cmd in the project folder does the same thing.

    Later rebuilds, without re-running the whole installer:

    .\getv\build_windows.ps1 -Target all -Mingw C:\mingw64

What the setup app will do, when it is published

Recorded here so it is clear what is and is not being promised. The setup app is not the game: it contains no ROM, no extracted assets, no decompiled game source and no playable goldeneye.exe. Every fresh installation stops at the ROM picker and cannot build until your own local file has passed verification. It needs no administrator access and does not install Git, Python or a compiler system-wide — it uses checksum-verified portable tools under your own user profile.

It is unsigned, so Windows SmartScreen will flag it as unrecognised. When an official package exists, verify both supplied SHA-256 files against your download before choosing More info → Run anyway, and never bypass that warning for a copy obtained from anywhere else. Details: docs/WINDOWS_INSTALL.md.

What a good install looks like

The build prints four counts. Every one of them should read 0 failed.

mac game: 167 built, 0 failed
mac assets: 746 built, 0 failed
mac audio: 40 built, 0 failed
mac port layer: 64 built, 0 failed

Any name in a FAILED: line is a real problem, not an expected one. The exact numbers differ per platform; the 0 failed does not.

Then the game starts and the launcher opens. On startup it logs its renderer, config path, save path, controllers and resolved key bindings — those lines are the first thing to look at if something is wrong, and the first thing to include in a bug report. Next: the launcher guide.

If something goes wrong

The installer stopped partway

Run it again. Every step checks for its own output and skips what is already done, so re-running resumes rather than restarting. On Windows, re-running GoldenEye-Native-Setup.exe in the same folder is the supported way to resume.

It says a dependency is missing

On Linux the installer prints the exact package-manager command for your distribution and stops rather than running sudo itself. Install that package and run the same command again.

It cannot find my ROM

Pass the path explicitly with --rom (macOS, Linux) or -Rom (Windows). The Windows setup app requires a big-endian .z64 specifically: it recognises .v64 and .n64 but refuses them, because the no-copy installer will not write a converted second file to your disk.

It built, but will not start

Keep the first meaningful error and the build summary. Then run the ROM-free port-layer tests, which need no game data at all:

bash getv/port/tests/run_tests.sh
powershell -NoProfile -ExecutionPolicy Bypass -File getv\port\tests\run_tests.ps1

Still stuck

Open an issue with the guided form, or ask an agent to prepare the report for you — see Help from an agent. Either way:

Never attach or paste a ROM, a save file, base.zip, extracted assets, generated asset source, a texture dump, an audio bank or your built goldeneye executable to an issue, a pull request, a chat message or any other public place. Renaming, zipping or encoding it does not make it allowed. Text logs, error messages and screenshots of the running game are exactly what is useful, and are welcome.

Deeper troubleshooting lives in docs/SETUP.md §7.
