Settings reference

Every user-facing setting, with its values, its default, the environment variable behind it, and whether the launcher exposes it. For the guided tour, start at The launcher.

Three rules that apply to everything below

  1. Every setting has the same name on the command line and in the config file. A row named resolution is resolution = 1920x1440 in the file and --resolution=1920x1440 on the command line. A bare --key value pair also works when the next argument does not begin with -. There is no separate CLI spelling to look up.
  2. The environment gate is the third spelling. Each row's gate column is the raw GETV_* variable the friendly key resolves to. You can set the gate directly — in the environment, in the config file, or as --GETV_STAGE=34 — and raw names are matched before friendly ones, so a friendly key can never shadow a gate.
  3. Precedence never changes: command line > environment > config file > built-in default. An environment variable always beats the file.

Almost everything needs a restart. 76 of the port's gates are read once into a static on first use. Only the three keys in Live keys change during a running game; the launcher's Play button restarts the process precisely so that everything else can take effect. Where a setting has an extra restart or platform limitation beyond that, the row says so.

Where the config file lives

The first of these that exists is used, and the rest are ignored.

  1. $GETV_CONFIG
  2. --config=PATH
  3. goldeneye.cfg in the same directory as the binary
  4. goldeneye.cfg in the platform user-data directory

If none exists and none was asked for, the game writes a commented template to location 4 and reads it back — that first-run write is how the port's tuned defaults actually reach you. The selected path is printed at startup, and that is the authoritative answer for your machine.

PlatformUser-data directory
Windows%APPDATA%\Goldeneye-Native\
macOS~/Library/Application Support/Goldeneye-Native/
Linux~/.local/share/Goldeneye-Native/

File format

# comment
; also a comment
key = value

Whitespace is trimmed. # and ; start a comment anywhere on a line. No sections, no quoting, no line continuations. An unrecognised key, or a line with no =, is reported on stdout rather than silently ignored. Values are lowercased before matching, except for save_dir and raw GETV_* passthrough, where case is meaningful.

The four command-line flags that are not settings

FlagEffect
--help, -hPrint the built-in usage summary and exit.
--list-cheatsPrint every named cheat with its id and whether it is live. Exits.
--config=PATHRead this file instead of searching. --config PATH also works.
--write-config[=PATH]Write the commented default config and exit. With no path, writes to the platform user-data directory, creating it.

Display and image quality

SettingValuesDefaultGateLauncherNotes
resolutionWIDTHxHEIGHT, or fullscreen / native1280x960GETV_WINDOWYes — VideoMinimum 320×240; anything smaller is rejected with an error and the default kept. fullscreen/native are shorthand for fullscreen = 1. The built-in default is clamped down in whole 4:3 steps if it would not fit the usable display area.
fullscreen0/1, on/off, true/false, yes/no0GETV_FULLSCREENYes — VideoDesktop builds start windowed. Also a live key.
aspect4:3, 16:9, auto (aliases 43, 169)noneGETV_ASPECTNoDoes exactly two things: picks a default window shape when resolution is unset (1280x960 / 1600x900), and warns if a set resolution disagrees with the requested aspect by more than 3%. An explicit resolution always wins; auto is a no-op. There is deliberately no second aspect control — two would aspect-correct twice.
widescreenon/offonGETV_WIDESCREENYes — VideoSingle-player only. on fills the real window at its own aspect with a wider field of view rather than a stretched image; off restores the original letterboxed framing byte-for-byte. Split-screen's per-viewport aspect is untouched either way, because it has not been audited against an arbitrary host window.
supersample1 or 21GETV_SUPERSAMPLEYes — VideoAnything else is rejected. 2 renders at double size and downsamples. It changes the framebuffer size and therefore the heap layout, so runs at different values are not comparable for anything more precise than "it looks better".
filteringpoint (nearest, n64), bilinear (linear), three-point (threepoint, 3point, default)three-pointGETV_FILTERING + GETV_POINT_FILTERYes — VideoTwo independent mechanisms sit behind this key and do not mean the same thing; the key sets both consistently so they cannot disagree. three-point is what the N64 RDP actually did.
msaa0–8, clamped0GETV_MSAAYes — VideoVerified working at 4 samples; the obtained sample count is printed at startup. The N64 had its own anti-aliasing and this port otherwise has none.
anisotropic0–16, clamped0GETV_ANISOYes — VideoClamped again at runtime to the driver's maximum, because asking for more than the hardware offers is a GL error rather than a silent downgrade. Applied only where the game already chose linear filtering, so the HUD, watch faces and text stay point-sampled and sharp.
mipmaps0 / 10GETV_MIPMAPSYes — VideoTrilinear filtering. Affects minification only — GL has no magnification mipmap mode — so close-up textures are unchanged. Meant to be tuned together with anisotropic.
fxaa0 / 10GETV_FXAAYes — VideoEdge antialiasing over the finished frame. An image-quality setting rather than a look, which is why it lives here and the CRT terms live in mods/crt_screen.
depth_bits16–32, clampeddriver defaultGETV_DEPTH_BITSNoThe driver decides. On Apple silicon the context comes back 32-bit whatever is asked for, including 16, so this cannot currently be used to reproduce N64 z-fighting. The obtained width is printed at startup as [getv][gl] depth buffer N-bit.
hd_textureson/offoffGETV_HD_TEXTURESYes — VideoUNVERIFIED Unlike filtering and widescreen, this path has had no compiler available to verify it against and is offered as reasoned-through rather than measured. An empty pack directory is a no-op, so turning it on without a pack costs one failed lookup per unique texture.
texpackdirectory pathhdtexturesGETV_TEXPACKYes — VideoResolved next to the executable if no such folder exists relative to the working directory. Textures are matched by FNV-1a 64 content hash: a file named <hash>.png replaces that texture; anything absent renders unchanged.
parallax0 / 11GETV_PARALLAXYes — VideoDoes nothing on its own. It decides whether a texture pack's <hash>_h.png height maps displace the diffuse UVs. There is no height data in the game's own assets, so with no pack it changes nothing either way.
crosshair_scale0.25–2.0 (alias reticle_scale)1.0GETV_CROSSHAIR_SCALEYes — Video1.0 is the retail sight size exactly. Applied after the 16:9 and PAL aspect corrections, so the shape never changes and only the size does. Out-of-range values are refused rather than clamped, so a typo is reported instead of silently becoming something else. GoldenEye+ asks for 0.6.
crosshair_colorRRGGBB hexFFFFFFGETV_CROSSHAIR_COLORNo — config only; the launcher has no colour controlIt tints, it does not recolour — measured, not assumed. The baked N64 sight carries its own hue and an RDP primitive multiply cannot pull it to a pure colour. On Windows, 2342 of 14400 reticle pixels change and a sampled pixel moves only from (153,170,176) to (153,173,179).
fov50–160, clamped100GETV_FOVYes — VideoVertical field of view as a percentage of the original. Applied on the way through rather than set once, because the game re-sets FOV every frame from the player's zoom state. It deliberately does not alter the value the game reads back, so the view widens and aim sensitivity behaves exactly as before. Also a live key.

Timing

framerate30, 50, 60, off (0, uncapped, unlimited)60 NTSC, 50 PALGETV_FPS, and GETV_REALCLOCK / GETV_TICKFIELDS depending on the valueYes — Video → TimingA cap above 60 is refused; off is the high-refresh setting. off also sets the real clock, because uncapped on the synthetic clock is the worst configuration available. 30 additionally sets two elapsed fields per update, so game time stays real while frame-counted systems drop to 30 Hz. Everything else in this reference is read once at startup and fixed for the process lifetime. That is a measured limit, not a missing feature, and it is why the launcher restarts the game rather than applying settings in place.

Raw gates

Around 250 development gates exist beyond the friendly keys above. Any of them can be set by its real name, in the config file or on the command line:

GETV_STAGE = 34
GETV_EXIT_FRAME = 61
./getv/build-mac/goldeneye --GETV_STAGE=34

The useful ones are covered in docs/MODDING.md. Four traps are documented because each one looks like a broken feature rather than a setting:

  • GETV_KEYBOARD_IDLE is on whenever GETV_EXIT_FRAME is set, so scripted input is ignored with no error printed — an input test looks like a null result rather than a disabled one.
  • Screenshots are always 24-bit BMP whatever extension GETV_SHOTPATH is given. Naming a file .png produces a BMP called .png.
  • GETV_AIM_SELFTEST takes a frame number, not a boolean, and it must be a frame after the locked-controls intro or no rising edge ever arrives.
  • run_tests.ps1 defaults to -Mingw C:\msys64\mingw64 while the project installs to C:\mingw64. Run it without the flag and it silently uses a different compiler.

One more worth naming because the symptom gets reported: coloured confetti on crate and barrel explosions is GETV_RGBA16BE, an RGBA16 byte-order gate that defaults to the corrected mode. It is not the paintball cheat. Measurements: docs/COLOUR_BUGS.md.

How this page is kept honest

Stated openly, because a settings reference is the easiest page on any site to let rot.

  • Every row here was taken from docs/CONFIGURATION.md, which is the authoritative reference, and cross-checked against getv/port/src/ge_config.c (the source of truth for keys, gates and defaults) and getv/port/src/ge_launcher.cpp (for the Launcher column, which was determined by checking which gate each launcher control actually writes).
  • Nothing here was written from memory. Where a value, default or limitation is not stated in those sources, this page says so rather than guessing.
  • This page is hand-maintained rather than generated. Generating it would mean parsing ge_config.c, which is a fragile contract with a file whose shape is not designed to be machine-read; the drift risk was judged smaller than the risk of a generator quietly producing a wrong table. The tradeoff is that updating this page is a step in the release checklist rather than something CI can prove.
  • The 250-odd raw GETV_* development gates are deliberately not enumerated here. They are development gates, not player settings, and docs/MODDING.md is where they live.

If a row disagrees with docs/CONFIGURATION.md, that document is right and this page has a bug — please report it.
