Known bugs & limitations

What is actually wrong, and what merely does not exist yet — kept apart on purpose, because they are different things and get confused constantly.

This list is not exhaustive, and it is not generated. It was assembled by hand on 2026-09-09 from two sources: the repository's open issues, and limitations stated in the project's own documentation. New problems get filed faster than a hand-written page gets updated, so treat the issue list as the authoritative answer and this page as an orientation.

Selection rule: every open issue was reviewed; those that describe a defect appear under Open defects, and the rest are feature work and appear on the roadmap instead. Limitations came from the documents each row cites.

Open defects

Issues that describe something broken, as opposed to something missing.

There are currently none. As of 2026-09-09, no open issue in this repository is labelled bug, and reviewing all 26 open issues by hand found none that describe a defect: they are feature work, CI hardening and documentation. Every bug that has been filed so far has been fixed — see Fixed, awaiting a release below.

That is a statement about what has been reported, not a claim that the software has no bugs. If you have hit one, please report it; it is the most useful thing you can do for this project.

Documented limitations

Real, known, and written down by the project itself. These are not filed as bugs because they are understood constraints rather than defects — but they are the things most likely to surprise you.

A wider window does not widen your view LIMITATION

severity cosmetic reviewed 2026-09-09 source docs/FAQ.md, docs/CONFIGURATION.md

Resolution and aspect are fully configurable, but the renderer fits the 4:3 view into whatever shape the window is rather than widening the field of view. The widescreen key fills the real window at its own aspect for single player; split-screen's per-viewport aspect is untouched either way, because it has not been audited against an arbitrary host window. Use fov if you want to genuinely see more. True aspect-aware widescreen is a roadmap item and is not done.

Above 60 fps, the game runs faster too LIMITATION

severity significant reviewed 2026-09-09 source docs/FRAME_TIMING.md, docs/VISION.md item 4

GoldenEye advances its clock in whole video fields, and on the default synthetic counter one rendered frame is one field by construction — so rendering faster runs the world faster. Measured: uncapped on the synthetic clock gives 812 fields/second where 60 is correct. A cap above 60 is refused rather than allowed to mislead you, and framerate = off switches to the real timebase instead. A fixed simulation tick with interpolated rendering is the correct fix; until it lands, 60 is the honest ceiling for unchanged gameplay. The project's own documentation calls this "the most consequential open problem in the project".

Co-op campaign is bring-up, not a mode ALPHA

severity significant reviewed 2026-09-09 source docs/COOP.md, docs/CONFIGURATION.md

Two to four players load into a solo mission with its own geometry, props and objectives, and every viewport renders. What is not adapted is everything the campaign authors around a single Bond: objectives, AI and cutscenes. Movement through the player API was verified over 6,001 frames on Train against a no-input control; what remains untested is two humans at two pads, which needs a person and a second controller.

The project's own documents disagree here, and that is worth knowing. docs/ROADMAP.md §M4 records co-op movement as verified and explains that the earlier "players do not move" conclusion was a measurement bug in the accessor, not a game bug. docs/VISION.md item 38 and docs/FAQ.md still carry the older conclusion. ROADMAP is the later and better-evidenced of the two; the older statements are stale and are recorded here rather than quietly resolved.

LAN play is alpha, and the approach itself is disputed DISPUTED

severity significant reviewed 2026-09-09 source docs/NETPLAY.md vs docs/PLAYER_API.md

A lockstep session exists in the tree. Whether the approach can work at all is disputed inside the project's own documentation: NETPLAY.md argues for lockstep and PLAYER_API.md argues against it from measurements. Both documents are deliberately kept rather than picking a winner prematurely, which is a decision, not an oversight. Online play sits downstream of the frame-timing work above.

HD texture support is unverified UNVERIFIED

severity minor reviewed 2026-09-09 source docs/CONFIGURATION.md § hd_textures

Off by default, unlike filtering and widescreen, and stated in the project's own words as offered "written-and-reasoned-through rather than measured" — no compiler was available to verify the path against. An empty pack directory is a no-op either way, so turning it on without a pack costs one failed lookup per unique texture. "Costs little if wrong" and "verified correct" are different claims and only the first holds.

Six settings parse, validate, and then do nothing BY DESIGN

severity minor reviewed 2026-09-09 source docs/CONFIGURATION.md § "Reserved, parsed but inert"

fog_per_pixel, muzzle_lights, audio_3d, ssao, shadows and per_pixel_lighting exist so the option surface is stable before the features land. Turning one on prints a not-implemented notice rather than failing silently. The project is explicit that a config key is not a feature and scores all of these OPEN. Full list.

debug_menu cannot work as a runtime setting BY DESIGN

severity minor reviewed 2026-09-09 source docs/CONFIGURATION.md § debug_menu

The leftover debug menu is compiled into every binary, but its trigger is gated on a macro that changes code generation in two places — one of which repurposes the Start button. Setting the key prints the rebuild command instead of pretending. Its level select does not work either: those entries are gutted no-ops.

depth_bits may be ignored by your driver PLATFORM

severity minor reviewed 2026-09-09 source docs/CONFIGURATION.md § depth_bits

On Apple silicon the context comes back 32-bit whatever is asked for, including 16, so the setting cannot currently be used to reproduce N64 z-fighting. The obtained width is printed at startup, so you can tell what you actually got.

Four traps that look like broken features GOTCHA

severity minor, developer-facing reviewed 2026-09-09 source docs/CONFIGURATION.md § "Things that will cost you an afternoon"

Collected because each one presents as a bug: scripted input is silently ignored whenever GETV_EXIT_FRAME is set; screenshots are always 24-bit BMP whatever extension you give them; GETV_AIM_SELFTEST takes a frame number rather than a boolean and needs a frame after the intro; and run_tests.ps1 defaults to a MinGW path the project does not install to, so it silently uses a different compiler. Details.

No Windows download, and no release of any kind NOT SHIPPED

severity significant for newcomers reviewed 2026-09-09 source docs/WINDOWS_INSTALL.md, docs/RELEASING.md

The no-code Windows setup app is an unsigned release candidate. There is no official download and no release automation: the workflow validates the candidate inside the runner and deliberately does not upload it. Do not download a setup executable from an Actions run or a third-party repost. Eight readiness gates are listed in docs/RELEASING.md and none of them is met yet. Use the developer path in the meantime.
